# 商标电子证据提交工作方法

适用场景：将旧版“说明页 + 证据正文”合并 PDF 整理为可编辑说明与可上传证据文件。

依据文件：`附件：商标业务电子证据提交指引26.5.9发文.pdf`。本项目样例核对日期为 2026-07-26；后续正式提交前应再次核对主管机关最新指引和系统限制。

## 默认交付结构

1. 一份可编辑 `.docx` 证据目录：
   - 列明证据编号、名称、来源、待证事实和逻辑页码范围；
   - 名称、顺序和页码与证据 PDF 完全一致；
   - 预留申请人签章和日期，正式提交前完成签名或盖章。
2. 一份可编辑 `.docx` 证据说明：
   - 每项证据单独起页；
   - 包含证据编号、证据名称、证据类别、争议商标、证据来源、待证事实、本组材料（如有）和申请人；
   - 不添加汇编页码。
3. 每项证据正文一个独立 `.pdf`：
   - 不含证据说明页；
   - 不含汇编过程新增的逻辑页码或物理总页码；
   - 原始证据自身固有的页眉、页脚、页码和页面身份信息予以保留；
   - 保持 A4，方向正确，内容清晰、完整。
4. 一份内部制作校验记录：
   - 源文件路径与 SHA-256；
   - 说明页、正文源页和逻辑页码映射；
   - 输出文件名、页数、大小和 SHA-256；
   - 移除的汇编页码对象数量；
   - 渲染和复核结论。

## 命名与页码

- 证据 PDF：`序号.证据名称（第X—Y页）.pdf`。
- 文件名中的证据名称应与证据目录一致。
- 逻辑页码只统计证据正文，在各 PDF 之间连续；说明页不计入。
- 同一证据正文实际页数必须等于文件名页码范围对应的页数。

## 指引约束

- 多个证据文件一般不超过 15 个。
- 每个 PDF 不超过 50 MB。
- 扫描材料建议 200—300 DPI；彩色材料至少 24 位彩色。
- 删除空白页、重复页，纠正歪斜和方向错误。
- 大量同类材料可合并为一个或少量 PDF，但不得造成文件名、目录和内容对应关系不清。
- 原始文件只读保留，任何拆分、页码对象移除或重命名均在工作副本上完成。

## 自动化入口

```bash
python3 scripts/prepare_evidence_submission.py \
  matters/<客户>-<商标>-<法域>/work/证据提交清单.json \
  matters/<客户>-<商标>-<法域>/deliverables/ \
  --audit-report matters/<客户>-<商标>-<法域>/audit/证据制作校验.json
```

正式交付前必须渲染 Word 和全部 PDF，检查页数、内容、裁切、空白、旋转、乱码和汇编页码残留；复杂案件再由 `trademark_audit` 独立复核。
