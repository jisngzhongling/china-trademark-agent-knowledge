# 中国商标代理知识库与自动化工作流

这是一个面向中国商标代理实务的知识库与 Codex 自动化工作流，涵盖案件接收、检索、风险分析、文书、证据整理、独立复核及申报前检查。

本仓库仅发布通用规则、公共研究资料、模板和通用脚本；客户案件、原始证据、工作稿、交付物、账号资料和未公开信息均由 `.gitignore` 排除。仓库内容不替代针对具体案件、程序时点和现行官方来源的专业核验。

## 使用方法

1. 在 ChatGPT/Codex 中打开本目录作为项目。
2. 新建任务并提供案件材料，或说明需要从 Gmail、Google Drive、Chrome 或本机应用获取什么资料。
3. 对复杂案件可直接要求：“按完整商标代理流程处理，并在最终提交前停下等待确认。”

## 全流程规范用字控制

规范用字核验已设为所有含文字商标的贯穿式控制项，不是单独的查字任务。案件从接收建档到申报前复核，均须保持原字符身份并检查：

- 原图逐字抄录、Unicode码位、OCR与人工识别；
- 中国《通用规范汉字表》收录情况；
- 涉及日文时，日本《常用漢字表》的现代通用字体与括注参考字体；
- 规范字、繁简体、异体字和日文字体的扩展检索；
- 原字符与建议规范字候选是否明确分离；
- 具体使用场景、法定例外和商标个案风险；
- DOCX、PDF、图片和申报页面是否存在缺字、替字、乱码或字体回退。

执行规则见 `knowledge/规范用字与日本字体全流程核验规则.md`，每案使用 `templates/规范用字核验记录模板.md` 留痕。没有发现异常时也要记录检查对象、日期和“未发现疑似非规范字符”的阶段结论；不需要为每案重复制作完整8105字名单。

已公开的公共研究资料：

- `knowledge/reference/2026-09-02_中国规范汉字与日本通用字体核验表_v01.xlsx`：收录中国规范汉字8105字、日本现代通用字体与括注参考字体重点项、代表性示例及宽口径跨表候选；
- `knowledge/reference/2026-09-02_中国规范汉字与日本通用字体核验说明_v01.docx`：说明数据范围、核验方法、使用边界及“嬢—孃—娘”等示例的推荐表述。

## 证据输出格式

- 商标业务电子证据提交默认交付一份可编辑 Word 证据目录、一份可编辑 Word 证据说明，以及按证据编号拆分的多个 PDF 证据正文。
- 证据目录列明编号、名称、来源、待证事实和页码，并预留申请人签章和日期；正式提交前须完成签章。
- 证据说明 Word 每项证据单独起页；证据 PDF 不含说明页，也不保留汇编流程新增的页码。
- 证据 PDF 使用 `序号.证据名称（第X—Y页）.pdf` 命名；逻辑页码在全部证据正文之间连续。
- 原文件自身已有的页眉、页脚或页码属于证据内容，默认保留；原件只读归档，不覆盖。
- 可使用 `scripts/prepare_evidence_submission.py` 从旧版合并 PDF 生成上述完整交付结构。

```bash
python3 scripts/prepare_evidence_submission.py \
  matters/<客户>-<商标>-<法域>/work/证据提交清单.json \
  matters/<客户>-<商标>-<法域>/deliverables/ \
  --audit-report matters/<客户>-<商标>-<法域>/audit/证据制作校验.json
```

生成器会校验原文件 SHA-256、说明页与证据页范围、逻辑页码连续性、A4 尺寸、15 个文件上限和单文件 50 MB 上限；同时记录每项证据的页数、移除页码对象数量、文件大小和交付文件 SHA-256。

`scripts/create_evidence_docx.py` 继续用于内部检索证据报告或用户明确要求的完整 Word 证据汇编。

## 推荐案件目录

```text
matters/<客户>-<商标>-<法域>/
├── source/        原始材料
├── evidence/      官方记录、网页截图和检索证据
├── work/          分析过程和工作稿
├── deliverables/  最终交付文件
└── audit/         复核记录和提交回执
```

## 自动化范围

系统已配置为高权限执行、实时检索和多智能体协作。普通读取可自动执行；连接器写操作按插件权限确认。正式提交、缴费、不可恢复删除、凭证和系统安全设置仍遵循产品要求的动作时确认。
